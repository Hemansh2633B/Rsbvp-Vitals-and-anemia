# Research methodology and current status

## Contactless pulse module

Existing research code extracts Green and POS traces from facial video and computes FFT/peak-based pulse candidates, motion classes, respiratory tachogram estimates and optional reference-device comparisons. The code retains historical correction heuristics for reproducibility; these are experimental and must be evaluated with correction on/off, by recording and motion condition. Current defaults are 0.7–3.5 Hz (42–210 BPM). CHROM is exposed as an independent RGB-trace transform. Offline ROI sampling retains separate forehead/cheek RGB traces with a conservative YCrCb skin-pixel heuristic; this is not landmark-based segmentation and is not guaranteed to exclude all non-skin pixels. Sampling frequency uses monotonic decoder timestamps where available, with nominal frame-rate fallback where decoder timestamps are absent or invalid. Frame gaps are counted for audit, not imputed as observations.

The browser live path requests camera access by action, runs MediaPipe Face Landmarker and ROI processing in-page, samples timestamped RGB, and offers a CSV export. Browser frequency estimates use timestamp regularization only across short gaps, independent Green/POS/CHROM transforms per viable ROI, estimator agreement, motion displacement and spectral concentration gates. A valid measurement requires adequate duration, a tracked skin ROI, reliable pulsatile spectrum, and estimator/window consistency. An absent or poor-quality signal must remain unavailable; synthetic tests validate implementation only, not physiology. The browser POS/CHROM DSP are experimental independent implementations; agreement with the Python offline implementation remains to be demonstrated. Respiratory estimates derived from pulse intervals are experimental. Pulse interval variability is PRV, not ECG HRV; no clinical or ECG agreement claim is established.

## Evaluation

For rPPG, compare Green, POS and CHROM independently by ROI and recording against synchronized reference signals. `research/rppg/validate_dataset.py` consumes only local explicit manifests under `RSBVP_DATA_ROOT` (or `--data-root`) and applies only a supplied, documented clock offset. Reference timestamps are checked for finite, strict monotonicity; robust interval jitter and maximum gaps are configurable. Accepted PPG/BVP windows require complete synchronized `[start,end)` coverage, are linearly interpolated to the measured median interval after gap/missing-sample checks, then bandpass-filtered and estimated with a Hann periodogram. Declared/original, timestamp-measured and effective rates plus rejection reasons are reported. ECG is intentionally rejected until validated R-peak processing is implemented; no frequency-domain ECG HR or ECG-HRV claim is made. Reports distinguish total windows, valid references, available estimates, valid pairs, participant/recording summaries and participant bootstrap where group count permits. Browser exports include a per-window analysis record (effective sampling rate, per-estimator estimates, quality score, availability status, rejection reason); see `docs/EXPORT_SCHEMA.md`. Quality-gate coverage must be read from `availability_status` fields, not from estimate presence; overlapping windows are correlated and are not independent subjects. Respiration requires a separate protocol. See `data/README.md` and `docs/SPRINT_3_AUDIT.md`.

The supplied Google Drive UBFC-rPPG archive was not accessible in the development workspace, and no COHFACE data was present. No actual dataset evaluation or physical camera test was performed. `reports/validation/validation.md` records `NOT RUN — DATASET NOT AVAILABLE`; deterministic fixtures are software verification only. Dataset-specific filenames, HDF5 keys, source citation, license, and synchronization mapping remain unverified and must be inspected before claiming support for a particular archive. For anemia, separate development and independent evaluation and report calibration and subgroup limitations; anemia remains outside this sprint.

## Sprint 8 — separated concepts, contract hardening, foundations (current status)

Quality verdicts are now six explicitly separated concepts — `face_tracking`, `roi_extraction`, `temporal_acquisition`, `pulse_signal`, `algorithm_agreement`, `availability` — reported individually on every verdict path; no blended score exists. A union ROI-coverage gate (≥ 0.50) joins acquisition/spectral/agreement checks for a `valid` verdict in both the browser and Python pathways. The browser motion detector purges the rolling analysis buffer on trigger. Browser and Python CHROM reject invalid inputs explicitly (non-positive/non-finite RGB, fewer than 8 samples, fs ≤ 7 Hz); in the browser each estimator is isolated so one failure degrades to `bpm:null` for that estimator only; in the legacy Python pipeline a CHROM `ValueError` yields an explicit unavailable CHROM estimate rather than aborting the analysis. Browser CHROM retains the in-band Hann periodogram as its band restriction; Python `chrom_rppg` retains its zero-phase Butterworth — documented as an intentional difference; parity remains demonstrated on the shared synthetic fixture only. MediaPipe failure paths (GPU→CPU fallback, permission denial, missing hardware, face loss/reacquisition, hidden tab, worker crash/termination, camera interruption) carry mocked regression tests; physical execution is NOT RUN. Anemia foundations gained a standardized input-image contract and explicit researcher-reviewed conjunctival-ROI annotation format with a machine-readable validator (`research/anemia/contract.py`; `docs/ANEMIA_IMAGE_CONTRACT.md`); still no model, no predictor, status NOT AVAILABLE. All dataset-level validation remains `NOT RUN — DATASET NOT AVAILABLE`.

The 16 sample GIFs were used for one thing only: a pipeline smoke check (`research/mmpd/mmpd_probe.py --gif-dir`) verifying that decode → Haar face detection → skin-masked forehead/cheek RGB traces → GREEN/POS/CHROM/ICA/PBV executes on real mobile-camera footage and reports unavailable states honestly (rotation/talking clips with face loss yield `unavailable` diagnostics, not fabricated estimates). No accuracy, agreement, or clinical metric exists for MMPD and none may be reported until the data-release agreement is signed and the dataset is acquired and inspected locally (`--inspect-mat`), after which the standard benchmark protocol (identical windows, no tuning, participant-grouped bootstrap) applies unchanged. ## Sprint 7 — quality verdicts, parity and research infrastructure

*(Sprint 7 text; superseded by the Sprint 8 section above — six separated concepts now.)* A dedicated quality layer (`gui/rppg_core/quality.py`; mirrored in the browser) decomposed the per-window verdict into five separately-computed concepts: (1) acquisition quality (channel clipping, mean brightness, under/over-exposure, dynamic range), (2) trace/ROI quality (usable-sample fraction, effective sampling rate, timestamp max-gap and dropped-interval fraction), (3) physiological signal quality (in-band spectral concentration, SNR vs the out-of-peak passband median, separation against the strongest competing in-band local maximum), (4) estimator agreement (max−min spread across independent Green/POS/CHROM-ROI estimates vs a 12 BPM ceiling), (5) availability (conservative composite). Status tokens are `warming_up`, `valid`, `low_signal_quality`, `excessive_motion`, `face_not_detected`, `roi_lost`, `insufficient_frames`, `irregular_timestamps`, `reacquiring`, `processing_error`. Unavailable windows report `bpm=null` with a human-readable reason; no plausible-looking number, zero-fill or stale substitution is ever emitted. Thresholds are documented research heuristics, not calibrated cut-offs; a strong spectral peak is not treated as proof of pulse origin.

Python and TypeScript spectral estimators were aligned to the identical formulation (symmetric Hann window; explicit `rfft`/DFT; identical passband, guard radius and separation rule) and are parity-tested on a shared synthetic fixture (`tests/fixtures/rppg_rgb_fixture.csv`; `gui/frontend/src/rppg/liveDsp.parity.test.ts` vs an independent Python reimplementation in `tests/fixtures/generate_rppg_rgb_fixture_expected.py`). Agreement beyond this fixture — real cameras, real optics, real skin — remains unproven; the browser POS/CHROM variants are documented as experimental.

The low-light POS false-accept (12–15 BPM error with an `ok` gate, Sprint 6 §6.3) was root-caused to plausible-but-wrong peaks passing a concentration-only gate. The new concentration/SNR/separation diagnostics flag the marginal windows in the synthetic low-light suite (`reports/research_validation/synthetic/reliability_synthetic.md`: POS `quality_ok_fraction` 0.556 native / 0.630 reference; synthetic data, not physiology). No gate is tuned to force any fixture to pass; the remaining exposure is cross-estimator disagreement and reference verification, which no in-window statistic can substitute for. See `docs/RELIABILITY.md`.

Per-window browser exports (`rsbvp.window-analysis.v1`) now carry selected display algorithm, ROI-level per-estimator BPMs, quality score, availability status, rejection reason, window bounds and effective sampling rate (`docs/EXPORT_SCHEMA.md`). Anemia tooling gained robust QA (illumination, exposure, clipping, measurable directional blur anisotropy, non-finite rejection), explicit mask validation with coverage reporting, percentile/histogram colour summaries with clipping and illumination indicators, and patient-level split-integrity checks; exact and near-hash duplicate grouping in the dataset inventory. No anemia model, predictor, screening or diagnostic capability exists or is claimed. All dataset-level validation remains `NOT RUN — DATASET NOT AVAILABLE`.
